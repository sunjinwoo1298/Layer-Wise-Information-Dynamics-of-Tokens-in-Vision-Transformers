# Limitations and disclosures (must accompany any use of the Phase 4 results)

## A. Data-access incident (disclosure — do not minimize or omit)
**P4-CONFIRM was not "never loaded" or "untouched", and no document may say so.** Before Gate 5, on 2026-11-17 (≈00:44 IST), the test `test_confirmatory_split_is_locked` — run as part of the full test suite after `frozen_method_configs.json` had been created — passed the confirmatory loader guard (its old assertion assumed that file did not exist). The loader decoded all 2,985 P4-CONFIRM images and wrote `data/p4_confirm_cache.pt`. The cache contained the **images, the ground-truth labels, the image IDs, source rows and encoded-image SHA-1s**, so labels and IDs *were* decoded and stored by that test, not images alone. Evidence of what happened or did not happen:
- No model inference, prediction, label comparison, metric, configuration selection or tuning used those data at that time; the test body contains no model call and its only output was a "DID NOT RAISE" failure line. All Gate 4 selections were produced from P4-DEV before the event and the frozen configuration was unchanged by it.
- Nothing in the session printed, displayed, exported or copied any image, label or ID from that cache; a code search found no other caller of the confirmatory loader.
- The cache was deleted, the test was rewritten to run in a temporary directory, and the loader gained a check of the frozen configuration bytes and dependency hashes. The full record is in `protocol_amendments.md` (unchanged).
- **Limit of evidence:** this account rests on the session record and code review. **There are no operating-system audit logs**, so access by another process on the machine cannot be ruled out by logs (none is known or suspected).
- The decision to retain P4-CONFIRM was made on the basis that inputs, not outcomes, were exposed. Readers may weigh this differently; the disclosure must appear in the paper.
- Separately and by design, the single Gate 5 run itself re-created `data/p4_confirm_cache.pt` (mtime 2026-11-17 09:18:40 IST, at run start). This cache is still on disk (hash in `evidence_inventory.csv`); this audit hashed its bytes for the inventory but did not load, decode, display or delete it.

## B. Scope limitations
- **Architecture:** one small model, DeiT-Tiny (`deit_tiny_patch16_224`, 12 blocks, 197 tokens). Results may not transfer to larger ViTs, other resolutions, or models trained with token reduction.
- **Data:** a **balanced 995-class subset** of the ImageNet validation set (3 images per class; classes 0–4 excluded because earlier phases exhausted them). It is not the natural validation distribution and is smaller than the full benchmark; 2,985 images give limited power for sub-1 pp differences.
- **Training-free adaptation only:** no method was fine-tuned; EViT-style is a reproduction-inspired variant (not official EViT; fusion is a raw attention-weighted sum; numerical parity unverified); ToMe is a faithful independent adaptation with official parity verified only for the tested configurations; DynamicViT and official EViT were not compared.
- **Different method-selection histories:** ToMe `(r, inflection)` and EViT-style κ were selected per budget on P4-DEV from large candidate grids (200 and 161 candidates; 2–10 feasible per cell); Phase 3 schedules were frozen earlier on other data and not re-tuned for the primary comparison; the supplementary Phase 3 re-selection used a 500-image dev subset; DiffRate used published rates untuned. Comparisons therefore do not have equal tuning effort or equal independence. P4-DEV results are selection data and not confirmatory evidence.
- **FLOPs matching is within ±1 pp**, not exact; realized FLOPs of compared cells differ by up to ≈1 pp (see Tables 2–3, 7). FLOPs are analytic and exclude auxiliary cost, which is reported separately.
- **CPU-only evaluation; latency is development-only and noisy.** Latency was measured on P4-DEV (not P4-CONFIRM), batch 25, 4 threads, with large IQRs and engine-dependent absolute values. No latency ranking is supported. Auxiliary seconds in the confirmatory run are summed timers on a shared CPU session and are indicative only.
- **DiffRate:** its merge semantics were **not verified against official DiffRate execution**; target 1.0 is "not applicable as released" (requested merge target exceeds available tokens) and its literal no-op run is a diagnostic only; DiffRate cells are exploratory, supplementary, and use DiffRate's own executed FLOPs rather than the primary grid.
- **Phase 3 replication** is a replication of the method on a new 995-class set, not an exact replication; its 24 comparisons share ten distinct schedule vectors.
- **Statistics:** multiplicity is controlled with Holm within stated families only; p-values in the saved CSVs are rounded to 6 decimals (so "<0.000001" stands for 0.0); bootstrap CIs are percentile intervals over images (class clustering ignored); exploratory/secondary results are not confirmatory claims.
- **Known documentation erratum** in the Phase 3 result file (string-sorted baseline vectors and one incorrect sentence) was corrected by an additive, dated erratum; schedules were always read as keyed dictionaries.
